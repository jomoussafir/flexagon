# Open the website

Double-click **Open Website.command** in this folder. Keep its Terminal window open
while using the website. The local site opens at **http://127.0.0.1:9410/**.

If macOS opens the shortcut as text, open Terminal, enter these two lines, then press Return:

```sh
cd /Users/msfr/Documents/flexagon
npm start
```

The first launch needs an Internet connection to download WordPress. Subsequent
launches reuse the database in `.local/wordpress`. Closing the server does not delete it.
Press Control+C in its Terminal window to stop the website.

## Sign in as administrator

Open **Local access.txt**, generated by the launcher. It contains your local-only
administrator email and password. Choose **Sign in** on the website and use these
details. Do not use these credentials on OVH.

Open the account menu beside your name, then click **Admin review** to browse the imported scanned collection. Filter by source,
category, difficulty or status; select a title to edit it. The list shows 50 problems
per page. The **PDF · p. …** links under each problem open its original PDF at the
recorded page in a new tab. The same links appear above the editor. Use **Back to
problem** or **Admin review** in the viewer to return. Reference books are visible
only to administrators.

Imported problems are unpublished, even when a language was verified in
the original site.

To add a new problem:

1. Click **Submit a problem**.
2. Choose its category, difficulty, source and keywords.
3. Write the first version or import a `.tex` file. Set its **Language name**.
   Use **Add a language** to choose or type another language; each version has
   its own title and statement, and all versions share the uploaded figures.
4. Upload SVG, PNG, JPEG or one-page PDF figures and use **Insert into statement**.
   As administrator, **Source figures** under Figures lists the redrawn vector figures
   of this problem's book page(s); click one to attach it, then insert it.
   Attached book figures are named like `colossal-p25-1.pdf`; the page shows the
   traced drawing and a **PDF** link opens the vector file.
5. Save a draft, or check the verified box in each ready language and click
   **Save & publish** as administrator.

A normal member sees **Submit for review** instead of publication controls.
The **Admin review** page shows submitted problems and their language approval status.
The **Members** page (admin account menu) lists every account's email with how many
problems it submitted and how many are published.

## Figures from the reference books

The books in `private-data/references` are scans, so their figures are traced into
vector PDF and SVG files by `tools/extract-figures.py` (needs Homebrew `poppler` and
`potrace`, plus Pillow, numpy and scipy for `python3`). Examples:

```sh
npm run figures:extract -- --source colossal --pages 24-32,138
npm run figures:extract -- --source colossal --problems
npm run figures:extract -- --all --problems
```

`--problems` traces every page cited by an imported problem. Results go to
`private-data/figures/<book>/`, with a `review/` folder containing one image per page
showing the detected boxes in red: check it when a figure looks incomplete or merged.
Rerunning a page replaces its traced figures.

Traced figures keep the look of the scan, so **Source figures** offers only figures that
have been redrawn cleanly. The drawings live in `tools/figures/<book>.py`, one small
function per figure (square, circles, arrows, labels…); `tools/redraw-figures.py` runs
them and writes `private-data/figures/<book>-redrawn/`:

```sh
npm run figures:redraw                      # every redrawing
npm run figures:redraw -- colossal-p138-2   # one figure
```

To add a figure, trace its page, look at the traced file, then add a drawing function
for its id in the book's module and rerun the tool (`--book moscow` for one book). Pure
illustrations (people, animals, scenery) and plain text passages are not redrawn. Figures are private, like the books; they are not
in Git and must be uploaded to OVH separately (see docs/ovh-setup.md).

## Navigation and personal progress

The home page opens **About**, displaying “Curated list of mathematical puzzles”
without an extra heading. The banner shows the icon and “Le Problem du jour”.
**Problem** opens the published problem selector after sign-in.
**Sign In** and **Create Account** are shown to visitors. Members also see
**Progress**, **Submit a problem**, and their account menu.

**Progress** starts with your solved problems. Filter by **Unseen**, **Bookmarked**,
**Attempted**, **Solved**, **Unsolved** or **All**,
and group the cards by category, difficulty or source. Search and filters can be
combined. Compact cards show the difficulty (1–5), title, source and status; their colour
runs from pale blue to purple. Click a card to read it, then mark it **Solved**.
The grid updates when you return. The **matching problems** count follows all active filters. Each group shows a completion count and bar.
Large groups show 24 cards initially and have a **Show more** button.

Unseen, bookmarked and attempted problems all count as unsolved. This view contains
only published problems and is private to the signed-in user. The imported scanned
collection remains in **Admin review** until an administrator publishes it.

## Try member registration

Use a private browser window to create a test account. The administrator’s
**Test inbox** contains confirmation and reset links. Copy the confirmation
link into the member’s window, confirm the email, then sign in.

All local emails are captured on this Mac; none are sent. On OVH, real outgoing email
must be configured and tested before registration is opened to users.

## What this does not launch

This launches WordPress on this Mac. It does not publish a public website or copy
this local database to OVH. Installation packages and the OVH
steps are in [docs/ovh-setup.md](docs/ovh-setup.md).

## Test in the iPhone simulator

Keep the website running, open **ios/Flexagon.xcodeproj** in Xcode, choose an
iPhone simulator and click Run (Debug configuration). The community app opens this
same website. Sign in with the same local account; the Problem tab shows the same
published collection. Use the bottom Back, Home and Reload buttons for navigation.

This connection is for the simulator on this Mac. Testing on a physical iPhone
requires a reachable website address; the Mac-local address cannot work there.
